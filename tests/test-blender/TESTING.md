# Actual Blender engine tests

This private workspace exercises the public source SDK and one-shot runtime against an explicitly supplied Blender installation. It creates a small CPU Cycles scene, renders a native PNG, saves a native `.blend` copy, reopens that copy in a fresh owned session, and independently inspects native geometry, shading, camera, lighting, and decoded image data. It also verifies that an ordinary script failure remains distinct from successful native shutdown and does not erase previously published files. MCP and upstream typia behavior are outside this suite.

Set `BLENDIA_BLENDER_EXECUTABLE` to the Blender executable and `BLENDIA_EXTENSION_SOURCE_DIRECTORY` to the actual extension packaging source directory. Prepare its ignored distribution license with the existing root command `pnpm extension:license` before running this source package. The target engine is Blender 5.2; unavailable or incompatible prerequisites fail explicitly rather than skipping or claiming a pass. After the workspace is wired and dependencies are installed, run `pnpm --filter @blendia/test-blender start`. TypeScript source packages execute without a build. Run the package's `build`, `lint`, and `evidence` scripts separately for their respective tool checks.

The suite first uses Blender's public `--command extension build`, registers an isolated offline USER repository, and runs `install-file --repo ... --enable`. A fresh native process loads that actual `bl_ext` addon, checks enabled registration and disable/enable behavior, compares every installed ZIP payload member with the built archive, and matches its license to the maintained repository-root LICENSE. Only the verified installed `__file__` directory supplies `headless_bootstrap.py` to all six scenarios. Installation failure stops the suite; it never switches to a source import. This native packaging and installation step is separate from a TypeScript distribution build and does not test manifest strings or typia behavior.

Optionally set `BLENDIA_TEST_OUTPUT_DIRECTORY` to an existing parent directory for retained runs. The runner reserves a unique child directory; otherwise it reserves one under the operating system's temporary directory. It prints that directory before execution and preserves the built extension ZIP, installed-payload observation, native PNG/.blend outputs, CPU seeds, native observations, and public runtime result reports on success or failure. Temporary bootstrap, descriptor, extension-repository, and Blender configuration storage uses a separate process-local child directory. No credentials or private bootstrap file bodies are copied into the reports. Upload only the explicit user files and reports, never the whole output tree: an unknown invocation can retain live private credentials beneath `private-runtime`. Cleanup never recursively removes a reported unknown invocation or published output.

The scene roundtrip uses a 128 by 128 CPU render with eight samples. It verifies PNG signature, dimensions, byte-stream continuity, equality of streamed and exported bytes, and native decoded pixel variation. It does not compare images to a snapshot or promise identical PNG hashes across Blender versions, machines, or repeated renders. A separate native load independently checks authored mesh vertices and face winding, material node inputs, camera aim, light parameters, and saved engine configuration. This is headless engine coverage, not automated clicks in Blender's graphical interface.

Five independent scenarios cover writer-lease rejection and reacquisition, object identity across real reconnect and fresh owned sessions, actual shared-mesh assignment refusal with independent native state inspection, no-camera and duplicate-render admission, four-artifact capacity and explicit release, and PNG/native-copy publication conflicts with explicit overwrite and preserved user backups. Each scenario reserves its own output directory and executes sequentially so a failure does not hide another behavior group. The small resource-admission renders use 32 by 32 pixels and the same CPU seed. Prepared source and checklist answers do not establish a passing run.

The suite deliberately leaves GUI clicks, native render cancellation, real ten-minute TTL expiry, aggregate 128-MiB image capacity, ambiguous native callback ownership, filesystem publication racers, external-image autosave refusal, current-session rename/delete/undo/load, direct working-filepath before/after inspection, parent loss, and unknown/timeout retention unclaimed. The public SDK does not expose several of those native controls; the tests add neither product hooks nor private protocol fallbacks to manufacture coverage. Remaining actual-host observations must stay explicit in the testing tracker.

Native packaging, installation, seed generation, and independent readback each have a ten-minute observation budget. Their sanitized `native-observations/*.jsonl` journals record the stage, observed PID, UTC observation time, outcome, code, and signal. This budget does not apply to the user's TypeScript execution or its native toolchain preparation. An expired observation stops new native/recipe admissions, preserves private files and user outputs, and unrefs only the runner's direct child handle; it does not kill Blender, certify descendant termination, retry, or replay a mutation. A public headless `unknown` result closes the same admission barrier. Later groups are reported as blocked, while ordinary assertion failures with known lifetimes still allow other independent groups to run. Unknown outcomes are not intentionally induced by this suite.
