# Observed environments and limits

Blendia's recorded observations cover specific workflows and environments, not every Blender version or operating system. The package remains unpublished. Use the [product guides](../README.md#usage-documentation) for setup and the [validation guide](design/automated-validation.md) for what the automated suites actually observe.

| Environment | Recorded scope | What it does not establish |
| --- | --- | --- |
| Blender 5.2.0 on Windows, graphical application | Live SDK scene operations, file/Text macros, native PNG and `.blend` output, and native reopening in the completed product slices | Every GUI action, full addon callback parity, or other Blender releases |
| Blender 5.2.0 on Windows, installed extension and owned headless execution | Actual ZIP installation and one-shot scene/render/save lifetime with explicit executable/extension paths | A daemon, durable private artifact handles after exit, or cancellation during blocking native rendering |
| Codex and Claude Code with the PR16 MCP server | Both hosts consumed native PNGs, answered blind visual questions, and completed without shell/file/image-open fallback | Other MCP hosts, arbitrary resource-blob presentation, or general model accuracy |
| Ubuntu 24.04, official Blender 5.2.0 Linux x64, CPU | PR18's accepted source and merged master passed six installed-engine groups with `ttsc` 0.36.0 | Other toolchain revisions or broader native behavior outside those scenarios |
| Unit CI on Ubuntu and Windows | PR18's accepted source and merged master passed nineteen first-party cases on both operating systems | Native Blender, graphical interaction, or host image consumption |
| Windows supported source commands on PR18 master | A fresh config command and owned headless scene/render/save run completed naturally; official Playwright MCP verified the resulting PNG | A startup SLA, controlled cache benchmark, historical root cause, or browser control of Blender's native UI |
| Other operating systems, Blender versions, and agent hosts | Not established by the recorded matrix | Universal compatibility or a fallback installation |

The [PR16 acceptance record](https://github.com/samchon/blendia/issues/5#issuecomment-6612053287) and [exact-source review](https://github.com/samchon/blendia/pull/16#pullrequestreview-5758452029) distinguish live connection ownership, native-image perception, normal cleanup, and CI. Earlier scene and headless observations belong to [PR14](https://github.com/samchon/blendia/pull/14) and [PR15](https://github.com/samchon/blendia/pull/15). [PR17's accepted validation record](https://github.com/samchon/blendia/issues/6#issuecomment-6614289519) preserves its eighteen-case unit and six-group engine results. [PR18](https://github.com/samchon/blendia/pull/18) accepted source `03ca8b8` after nineteen-unit, type, Evidence, build and Ubuntu engine checks; its merged master also passed those workflows. Windows engine and GUI/host observations were reused only after review of their unchanged execution paths and payloads, not presented as fresh executions on every head.

## First-use preparation

Allow for native compiler/plugin preparation before user TypeScript begins. A nested native Go plugin build completed successfully in 801.166 seconds; the first native emit was manually interrupted with an unknown lifetime, while a separate later native emit returned zero in 413.840 seconds and its CLI completed naturally. Later observed runs took roughly 28–35 seconds under different conditions. These are distinct observations, not a controlled benchmark or proof that the interrupted emit eventually succeeded. The original silent configuration failure and suspension causes remain unresolved, and no startup speedup is promised.

The [native startup guide](design/native-startup.md) distinguishes the separate default-environment TEMP failures from the original silent exit 1, whose failure and retry both explicitly selected the same physical TEMP/TMP. Supported launchers prepare storage automatically before public `ttsx`; fully absolute usable settings are preserved or aligned, and unsafe/cwd-dependent settings receive owned storage without repeated manual TEMP setup. PR18's cwd-independent path/selector correction passed its affected source checks and public-entry verification. GUI File/Text and both coding-agent hosts succeeded on `900527a` with normal postflight, with bounded reuse approved for the accepted source. The first 0.36.0 observer's timestamp-parsing defect prevents conclusions from that observer; it does not invalidate later independent observations or establish the original failure cause.

On merged master `3a0201f`, a fresh config command completed in 7.799 seconds and an actual source-first headless run completed in 32.668 seconds with CLI, script and Blender exits all zero. The run authored the scene, rendered and saved PNG/.blend outputs, and removed its private workspace. Official Playwright MCP opened that same PNG, verified its bytes and 512×512 decoding, and captured the blue pyramid, gray floor and shadow without clipping or broken output. The [consolidated record](https://github.com/samchon/blendia/issues/3#issuecomment-6623185019) preserves these current results and the earlier interrupted run's unknown outcome. They do not reconstruct historical missing diagnostics, explain old suspension actors, or certify later source changes.

The [canonical first-run guide](design/script-jobs.md#first-run-preparation) explains project compiler/dependency setup, possible network/Go/cache preparation, and preserving the final observed outcome. Its [dated timing evidence](https://github.com/samchon/blendia/issues/3#issuecomment-6601366606) remains separate from the [later MCP acceptance observations](https://github.com/samchon/blendia/issues/5#issuecomment-6612053287). Metadata-only doctor output does not execute native prerequisites. Host startup, tool-call, SDK-response, native-observation, and cooperative shutdown budgets are distinct; none promises process-tree cancellation or rollback.

Blendia exposes bounded authored operations and explicit scene/process/file lifetimes. It does not provide full `bpy` parity, a replacement TS IDE, universal synchronous addon callbacks, automatic replay of uncertain mutations, or guaranteed cancellation. Explicit saved user PNG and `.blend` files outlive the owned process; private bridge artifacts and their MCP resource identities do not.
