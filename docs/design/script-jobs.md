# Shared script jobs and diagnostics

Tracking: [execution #3](https://github.com/samchon/blendia/issues/3), [validation #6](https://github.com/samchon/blendia/issues/6), and [parent #1](https://github.com/samchon/blendia/issues/1). This planning seed opens the next Draft before implementation, following Blender file/Text macros. The baseline already supports source-first project execution; this slice gives real consumers the same bounded execution/result owner rather than introducing a daemon or another TypeScript runtime.

## Scope

`packages/runtime` owns one common internal launch/lifecycle implementation, with actual inherit and capture stdio policies. Existing runProjectScript/runTextMacro preserve inherited stdin/stdout/stderr, TTY and input behavior; they are not converted into captured jobs with forwarding. The new process-local ScriptJob uses capture policy, bounded log cursor state and the same Text staging/result ownership. Metadata/argv/cwd/environment/spawn/error/close/staging must not be implemented twice. CLI is a foreground terminal/machine adapter, Blender observes that public CLI, and the later MCP server directly consumes the captured runtime API. Each object shape remains a named interface in its own file.

Captured-job child stdin is ignored and stdout/stderr are piped and continuously drained; the captured core never automatically forwards to parent streams. Incremental UTF-8 decoding, stream tags, byte-bounded retained logs/pages, cursor gap/truncation signals, secret redaction across chunks and terminal/unknown outcomes are owned by first-party logic. Default CLI run preserves legacy inheritance; UI machine/job mode renders captured events, and MCP uses capture only so protocol stdout and input stay isolated. A direct launcher result does not prove every descendant stopped or that Blender mutations rolled back. Live records are never silently evicted; terminal state/retention and close ownership are explicit.

Provide discovery only in an explicit descriptor directory, returning bounded sanitized metadata without tokens. File presence is not a live-session proof. Doctor distinguishes actual Node/public ttsx/project/dependency metadata from unchecked execution; it does not test Go/network/native-plugin preparation or promise first-use readiness. Do not compile a dummy project, run an import probe or change global environments.

No global daemon, durable job lookup between CLI invocations, background-start/inspect promise, cancellation, transaction rollback or mutation replay is included. The first jobs API explicitly reports cancellation unsupported: killing a direct launcher cannot establish descendant termination. Python keeps ownership of its private input, while runtime owns the Text sibling. Preserve current file/Text grammar, source-only local execution and public ttsx metadata resolution.

## Frozen API and ownership

The accepted process-local API is startScriptJob with a named file/Text request union, getScriptJob for the same owner incarnation, and ScriptJob.inspect/readLog/wait/close. Phases are starting, running, draining and terminal; terminal outcomes distinguish exited, launch-failed and unknown. Admission is capped at16 records, reclaimed by explicit terminal close; active close is refused and no automatic eviction, TTL, cancellation or cross-CLI lookup is promised. This memory bound does not bypass Blender's exclusive writer/BUSY contract.

Captured logs retain at most64 KiB and1024 entries; a page returns at most16 KiB and128 entries. A cursor is a safe integer at least0, and a cursor beyond the current tail is refused. byteLimit is a safe integer from4096 through16384. nextCursor names the first unreturned entry; earliestCursor, gap and hasMore distinguish retention loss from more available data. Preserve UTF-8 boundaries and known-token redaction across chunks in every log/diagnostic path. Never serialize original connection/options/environment or raw descriptor JSON into public job state or metadata. Normalize credential-bearing discovery/probe transport errors and internal diagnostics to fixed sanitized findings; preserve actual child TypeScript diagnostics and stack output in bounded logs after known-token redaction.

discoverBlenderSessions takes IBlenderDiscoveryOptions and returns IBlenderDiscoveryResult with sessions typed as IBlenderDiscoveredSession[], fixed sanitized string issues, truncated and probeTruncated. It requires an explicit directory, scans nonrecursively with at most256 entries,32 descriptors and16 KiB per regular session-*.json file, and excludes symlink/nonregular credential inputs. Default discovery opens no socket. Explicit probes perform at most8 sequential bounded SDK hello/identity checks with finally disconnect; report BUSY without retry/stealing/killing and disclose the brief idle lease. truncated describes directory/descriptor limits; probeTruncated describes the requested probe budget only. A valid descriptor alone is not a live proof.

doctorProject takes optional IProjectDoctorOptions and returns IProjectDoctorReport. It reports the current Node execution/version, public runtime-owned ttsc metadata/bin.ttsx readability/version, cwd and an explicit or nearest tsconfig candidate, plus actual SDK/typescript dependency metadata. execution is not-tested; it does not claim the compiler actually selected that candidate or that native/Go/network/plugin execution works. Invalid options/cwd are refused; missing metadata/dependencies/config produce fixed diagnostic strings. The five discovery/doctor DTOs each live in their own same-named interface file; sessions is the actual field name, and issues are fixed strings rather than anonymous nested object shapes.

CLI adds sessions --directory with optional --probe/--probe-timeout-ms and doctor with optional --cwd/--project. Default run keeps inherited streams; machine/job mode consumes capture. The runtime launch/job modules own child lifecycle, captured logs and Text staging; separate runtime discovery/doctor modules own bounded metadata inspection and optional session probes. The CLI owns grammar and terminal/machine rendering, the Python extension owns its outer CLI observation and private input, and the test workspace owns meaningful units of the implemented first-party state/log/grammar logic. No separate SDK/protocol/daemon package is required for these responsibilities. This is the next Draft's accepted contract, not an assertion that its API already exists in the PR10 baseline; implementation starts only after that Draft is opened.

## Acceptance

- File and Text paths share the actual launch/lifecycle implementation and preserve original source, process result, staging disposition and existing inherited three-stream behavior. No captured-forward substitute or duplicate spawn/staging implementation changes that contract.
- Captured arbitrary child output and stdin cannot corrupt or consume a future MCP stdio stream; captured logs have no automatic parent output, and only their CLI adapters render terminal/machine events.
- Meaningful first-party units cover actual UTF-8 chunk/cursor/gap/budget/state/redaction logic; no child fixture, static-config, upstream or artificial-helper suite is added.
- Explicit-directory discovery separates scan truncation from optional-probe incompletion, stays bounded/token-free and does not present files as live. Doctor clearly separates actual metadata from untested compiler/Go/network/native-plugin execution.
- One required actual product observation verifies source CLI/Blender adapter logs, terminal versus bootstrap outcome, EOF/staging/input cleanup and the documented unknown/cancellation limits.
- Applicable Evidence, independent complete-diff review, exact-head COMMENT self-review and all configured CI pass before immediate merge.

The prior830s/395s intervals and initial silent config failure remain separate observations. Instrument the already-required next real product run to identify preparation regions; neither this planning seed nor a job ID claims a startup improvement.
