## Supported launch paths

Normal root commands, including `pnpm blendia`, keep their existing arguments. Their tool leaves use Node's public `--require` to run [config/nativeBootstrap.cjs](../../config/nativeBootstrap.cjs) before the installed public compiler, `ttsx`, or Evidence executable. CLI and MCP package `start` scripts use their shipped `nativeBootstrap.cjs` shim before public `ttsx` and `src/bin.ts`. This compiler-independent environment step must precede TypeScript initialization; a TypeScript helper would initialize too late. The [development rule](../../.agents/skills/development/SKILL.md#pre-native-environment) owns this narrow CJS exception.

For a direct MCP launch outside the checkout cwd, use the absolute package shim as a Node `--require` argument before the absolute public `ttsx` target and source entry, as shown in the [MCP guide](mcp-agent-tools.md#stdio-host-setup). The shipped public preload paths are `@blendia/mcp/native-bootstrap`, `blendia/native-bootstrap`, and `@blendia/runtime/native-bootstrap`. The environment producer itself is internal, consumed by the real preload/runtime rather than exposed as another package API. No blanket third-party `ttsx` hook or global `NODE_OPTIONS` change is installed.

The [internal environment producer](../../packages/runtime/native/prepareNativeEnvironment.cjs) accepts a temporary parent only when it is fully absolute and passes actual allocation and physical parent/child identity checks. POSIX requires a leading `/`; Windows accepts drive-plus-separator or a complete UNC server/share path. Relative paths and Windows drive-dependent forms such as `C:temp`, `\temp`, or `/temp` are not interpreted against the parent cwd; an unusable selected primary receives verified process-owned fallback storage. This keeps preparation valid when the project child uses another cwd. No manual physical TEMP path is required for each supported launch.

Windows key selection sorts names lexicographically and uses the first case-insensitive alias, even when its undefined value suppresses a later alias. Standard primary selection follows Windows `TEMP`, `TMP`, then the system-root temporary path; POSIX names are case-sensitive. When effective `TEMP`, `TMP`, and `TMPDIR` are all fully absolute and identify the same physical root, the input is preserved verbatim. Missing, conflicting, or relative secondary settings are aligned to the usable primary's safe absolute value, and the selected healthy primary string is preserved. Alignment or fallback removes Windows case aliases before assigning the canonical three keys in the copied environment; unrelated entries and caller/global state remain unchanged. This aligns standard Node and Go selectors, which have different priorities, without changing Go override/cache variables or promising every privileged execution context.

The quiet [preload](../../packages/runtime/native/bootstrap.cjs) applies the prepared copy only to its current Node process; failures reject initialization through an ordinary exception. Runtime prepares a copied child environment before launching a project's public `ttsx`. Blender's macro launcher adds the shipped CLI shim before Node starts either the source CLI or its package's JavaScript entry, using the existing CLI selection fields. Cwd, argument ownership, inherited/captured stdio, managed/current Node choice, exit interpretation, source imports, native security checks, and plugin discovery keep their existing roles. An arbitrary external process that fails before importing Blendia still needs preparation at its own outer launch boundary; the runtime cannot repair an already-failed compiler initialization.

The automatic fallback is intentionally retained because native descendants may still depend on it after a direct launcher closes. Uncertain allocations are retained too; only the verified still-identical empty allocation check is removed. No recursive fallback cleanup, process-tree termination, cache purge, global environment mutation, or security-policy change is implied. Treat retained scratch and copied environment data as private, not uploadable user artifacts.

Run A failed while acquiring file-backed native-output capture, before the native-attempt trace boundary; run B reached that boundary. Recovered contemporaneous command/output evidence corrects the original silent-failure account: the first failure and its successful diagnostic retry both explicitly selected the same physical TEMP/TMP. Claims that those assignments were unpreserved or added only for the retry are withdrawn. The original returned output was untruncated and wrapper-only; display truncation does not explain its absent inner diagnostic, but the record also cannot establish that no inner diagnostic was ever produced. An independently captured outer stderr file can establish its own observed bytes, but cannot reconstruct missing historical inner stderr. The first 0.36.0 run produced zero native trace files, consistent with its capture-allocation exception occurring before native-attempt tracing. Its resource observer transformed the root creation timestamp incorrectly during date parsing, so CPU, I/O, thread, full-lineage, and descendant-absence observations are unavailable. The observer defect was preserved without a product replay and is separate from the explicit config stderr and exit code.

An earlier interrupted headless observation retains a null exit and unknown outcome; missing terminal records are not replaced with the newer run's result. The [consolidated tracker](https://github.com/samchon/blendia/issues/3#issuecomment-6623185019) preserves raw provenance and causal limits.
