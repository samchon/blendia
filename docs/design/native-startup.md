## Supported launch paths

Normal root commands, including `pnpm blendia`, keep their existing arguments. Their tool leaves use Node's public `--require` to run [config/nativeBootstrap.cjs](../../config/nativeBootstrap.cjs) before the installed public compiler, `ttsx`, or Evidence executable. CLI and MCP package `start` scripts use their shipped `nativeBootstrap.cjs` shim before public `ttsx` and `src/bin.ts`. This compiler-independent environment step must precede TypeScript initialization; a TypeScript helper would initialize too late. The [development rule](../../.agents/skills/development/SKILL.md#pre-native-environment) owns this narrow CJS exception.

For a direct MCP launch outside the checkout cwd, use the absolute package shim as a Node `--require` argument before the absolute public `ttsx` target and source entry, as shown in the [MCP guide](mcp-agent-tools.md#stdio-host-setup). The shipped public preload paths are `@blendia/mcp/native-bootstrap`, `blendia/native-bootstrap`, and `@blendia/runtime/native-bootstrap`. The environment producer itself is internal, consumed by the real preload/runtime rather than exposed as another package API. No blanket third-party `ttsx` hook or global `NODE_OPTIONS` change is installed.

The [internal environment producer](../../packages/runtime/native/prepareNativeEnvironment.cjs) checks the effective caller temporary parent using actual allocation, physical parent/child identity, and a removable empty check directory. On Windows it sorts keys lexicographically and selects the first case-insensitive key before omitting undefined values; an undefined earlier alias can suppress a later differently cased alias. Its effective temporary path follows Windows `TEMP`, `TMP`, then the system-root temporary path, while POSIX names remain case-sensitive. Healthy input key spelling, aliases, values, and unrelated environment entries are preserved. For an unsafe location it verifies a newly reserved process-owned directory beneath the physical home directory; only fallback removes every Windows case alias of `TEMP`/`TMP`/`TMPDIR` before assigning those canonical keys in the copied child environment. Users do not need to supply a manual physical TEMP path for every supported launch.

The quiet [preload](../../packages/runtime/native/bootstrap.cjs) applies the prepared copy only to its current Node process; failures reject initialization through an ordinary exception. Runtime prepares a copied child environment before launching a project's public `ttsx`. Blender's macro launcher adds the shipped CLI shim before Node starts either the source CLI or its package's JavaScript entry, using the existing CLI selection fields. Cwd, argument ownership, inherited/captured stdio, managed/current Node choice, exit interpretation, source imports, native security checks, and plugin discovery keep their existing roles. An arbitrary external process that fails before importing Blendia still needs preparation at its own outer launch boundary; the runtime cannot repair an already-failed compiler initialization.

The automatic fallback is intentionally retained because native descendants may still depend on it after a direct launcher closes. Uncertain allocations are retained too; only the verified still-identical empty allocation check is removed. No recursive fallback cleanup, process-tree termination, cache purge, global environment mutation, or security-policy change is implied. Treat retained scratch and copied environment data as private, not uploadable user artifacts.

The 0.35.0 pair preserved selected source/configuration and installed-entry hashes, while using different temporary coordinates sequentially. That evidence does not establish every compiler/native/cache byte or a controlled timing benchmark. Run A failed while acquiring file-backed native-output capture, before the native-attempt trace boundary; run B reached that boundary. No new invocation, benchmark, cache purge, security change, forced process action, or global environment change follows merely from documenting this pair.

Native trace result fields `stdout: null` and `stderr: null` are recorded before file-backed output capture is read. They do not prove the child produced empty output. An independently captured outer stderr file can establish its own observed bytes, but cannot reconstruct missing historical inner stderr. Similarly, the older 830/395-second source-log creation-to-last-output intervals belonged to different programs, including an intentional application-error run; they are not isolated preparation stopwatches.

The first 0.36.0 run produced zero native trace files, consistent with its capture-allocation exception occurring before native-attempt tracing. Its resource observer transformed the root creation timestamp incorrectly during date parsing, so CPU, I/O, thread, full-lineage, and descendant-absence observations are unavailable. The root was absent at a later read-only check, but that does not establish that every descendant stopped. The observer defect was preserved without a product replay and is separate from the explicit config stderr and exit code.
