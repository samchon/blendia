## Supported launch paths

Normal root commands, including `pnpm blendia`, keep their existing arguments. Their tool leaves use Node's public `--require` to run [config/nativeBootstrap.cjs](../../config/nativeBootstrap.cjs) before the installed public compiler, `ttsx`, or Evidence executable. CLI and MCP package `start` scripts use their shipped `nativeBootstrap.cjs` shim before public `ttsx` and `src/bin.ts`. This compiler-independent environment step must precede TypeScript initialization; a TypeScript helper would initialize too late. The [development rule](../../.agents/skills/development/SKILL.md#pre-native-environment) owns this narrow CJS exception.

For a direct MCP launch outside the checkout cwd, use the absolute package shim as a Node `--require` argument before the absolute public `ttsx` target and source entry, as shown in the [MCP guide](mcp-agent-tools.md#stdio-host-setup). The package exposes `@blendia/mcp/native-bootstrap`; the CLI exposes `blendia/native-bootstrap`. Runtime exposes `@blendia/runtime/native-bootstrap` and `@blendia/runtime/native-environment`. These are shipped public package subpaths. No blanket third-party `ttsx` hook or global `NODE_OPTIONS` change is installed.

The [environment producer](../../packages/runtime/native/prepareNativeEnvironment.cjs) exports `prepareNativeEnvironment(environment?)`, returning an environment copy, an optional automatic fallback `directory`, and `retainedDirectories` for uncertain allocations. It checks the effective caller temporary parent using actual allocation, physical parent/child identity, and a removable empty check directory. Healthy caller settings and other environment keys remain unchanged. If that effective location is unsafe, it automatically reserves a private process-owned directory beneath the physical home directory and verifies its identity and nested allocation before setting only process-local `TEMP`, `TMP`, and `TMPDIR`. Users do not need to supply a manual physical TEMP path for every supported launch.

The quiet [preload](../../packages/runtime/native/bootstrap.cjs) applies the prepared copy only to its current Node process; failures reject initialization through an ordinary exception. Runtime prepares a copied child environment before launching a project's public `ttsx`. Blender's macro launcher adds the shipped CLI shim before Node starts either the source CLI or its package's JavaScript entry, using the existing CLI selection fields. Cwd, argument ownership, inherited/captured stdio, managed/current Node choice, exit interpretation, source imports, native security checks, and plugin discovery keep their existing roles. An arbitrary external process that fails before importing Blendia still needs preparation at its own outer launch boundary; the runtime cannot repair an already-failed compiler initialization.

The automatic fallback is intentionally retained because native descendants may still depend on it after a direct launcher closes. Uncertain allocations are retained too; only the verified still-identical empty allocation check is removed. No recursive fallback cleanup, process-tree termination, cache purge, global environment mutation, or security-policy change is implied. Treat retained scratch and copied environment data as private, not uploadable user artifacts.

## Separate observations

| Observation | Recorded fact | Causal limit |
| --- | --- | --- |
| Original silent configuration failure | The public config wrapper returned exit 1 | The original inherited environment, inner native status/error/stderr, exact source hash, and full input provenance were not captured |
| Historical 0.35.0 inherited TEMP/TMP run A | `config:check` returned 2 with a physical-parent temporary-directory exception before native attempt tracing began | This identifies that observed prerequisite boundary, not the original exit-1 cause or the OS actor behind the physical namespace difference |
| Historical 0.35.0 owned physical TEMP/TMP run B | The same public command returned 0 and its trace contains a native attempt returning status 0 | B's trace was present; the earlier blank-sink claim was an observer table-display error and is retracted |
| First 0.36.0 inherited TEMP/TMP config run | The actual public subprocess returned 2 with the physical-parent exception; selected 13 source/compiler/native hashes and sizes stayed unchanged | This confirms that upgrading alone did not remove the observed prerequisite failure; it does not identify an OS actor or reproduce the original silent exit 1 |
| Native Go plugin build | The nested build returned status 0 after 801.166 seconds | This was a successful build interval, not the whole user-program duration or proof of a CPU/network/lock cause |
| First native emit | Its trace has an attempt without a returned result; it was manually interrupted with an honest unknown lifetime and retained input/stage | Suspended thread snapshots do not identify a suspending actor, deadlock, or natural completion |
| Separate later native emit | It returned status 0 after 413.840 seconds and that separate CLI invocation completed naturally | This is not completion of the interrupted first emit and does not establish the earlier suspension cause |

The 0.35.0 pair preserved selected source/configuration and installed-entry hashes, while using different temporary coordinates sequentially. That evidence does not establish every compiler/native/cache byte or a controlled timing benchmark. Run A failed while acquiring file-backed native-output capture, before the native-attempt trace boundary; run B reached that boundary. No new invocation, benchmark, cache purge, security change, forced process action, or global environment change follows merely from documenting this pair.

Native trace result fields `stdout: null` and `stderr: null` are recorded before file-backed output capture is read. They do not prove the child produced empty output. An independently captured outer stderr file can establish its own observed bytes, but cannot reconstruct missing historical inner stderr. Similarly, the older 830/395-second source-log creation-to-last-output intervals belonged to different programs, including an intentional application-error run; they are not isolated preparation stopwatches.

The first 0.36.0 run produced zero native trace files, consistent with its capture-allocation exception occurring before native-attempt tracing. Its resource observer transformed the root creation timestamp incorrectly during date parsing, so CPU, I/O, thread, full-lineage, and descendant-absence observations are unavailable. The root was absent at a later read-only check, but that does not establish that every descendant stopped. The observer defect was preserved without a product replay and is separate from the explicit config stderr and exit code.

## Remaining verification boundary

Use the supported public source commands with the selected toolchain and retain actual status, diagnostics, trace presence, and relevant input/environment identity. The producer's bounded actual-filesystem observation established automatic fallback selection, healthy-environment preservation, and caller/global nonmutation; it ran no compiler. A nineteenth first-party unit covers the real healthy-parent/copy/check-allocation ownership policy, while the redirected default host and native initialization require actual public-entry observation. These source and filesystem observations do not establish corrected compiler or Blender success.

Keep failed prerequisites observable rather than skipping them into a green result. Existing development checks, native guards, plugin discovery, captured/inherited stdio, MCP protocol stdout, and private artifact ownership retain their roles; no upstream typia revalidation, fake child/server, or MCP E2E is added. The environment glue does not replace `ttsx`, reinterpret TypeScript, or implement another execution runtime.

The original silent failure and old suspension actor remain unproven. A successful newer invocation cannot retrospectively supply the omitted observations, and faster later runs do not establish a solved cause or a startup guarantee. Functional acceptance and a bounded evidence review do not make the remaining required diagnosis optional or establish that the whole mission is complete. Preserve the dated [startup evidence](https://github.com/samchon/blendia/issues/3#issuecomment-6601366606), original artifacts, and explicit unknown outcomes alongside new tracker results.
