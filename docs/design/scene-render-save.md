# Scene authoring, native render and persistent outputs

Tracking: [SDK #2](https://github.com/samchon/blendia/issues/2), [lifecycle #3](https://github.com/samchon/blendia/issues/3), [MCP #5](https://github.com/samchon/blendia/issues/5), [validation #6](https://github.com/samchon/blendia/issues/6) and [parent #1](https://github.com/samchon/blendia/issues/1). This planning contract precedes implementation of the GUI scene-to-output slice. Headless process ownership and MCP/native image consumption follow in separate Drafts. The declarations below describe accepted work, not implemented capabilities.

## Ownership and compatibility

packages/sdk owns typed public methods and extraction of its actual socket/request responsibility into an internal BlenderConnection to keep source files below 500 lines. blender/extension/scene_data.py owns scene operations; commands/server/routing integration has one owner. Native rendering, artifacts, save-copy and atomic destination publication belong to separate focused extension modules sharing publication.py where there are two real consumers. Every concrete TypeScript object shape, nested payload, cursor and variant has its own named interface file. No generic RPC framework or separate protocol package is introduced.

Preserve authenticated protocol version 1, 1 MiB BE32 UTF-8 JSON messages, one pending request, exact current-generation request envelopes, the 30-second response timeout and no automatic replay. Negotiate new capabilities per method without breaking connections to older bridges. Scene data uses existing session/generation handles, main-thread bpy execution and Object Mode/Global Undo/private undo/effects contracts. No full RNA/codegen/bpy parity, arbitrary Python execution, Blender rewrite or Three.js integration is included.

## Scene surface

- inspectScene(query) uses scene.inspect with limit default 50/max 100 and an opaque cursor bound to session, generation and scene. Return scene identity/name/frame/active camera/object count, UID-ordered object snapshots and next cursor. Each page is fresh; cross-page snapshot consistency is not promised.
- createMesh(options) uses mesh.create with one bulk vertices/faces request. Bound 8192 vertices, 8192 faces and 32768 corners independently of the wire cap. Require finite coordinates with absolute value at most 1e20, faces of at least three distinct vertices and integer in-range indices. Validate before linking owned data; never silently repair topology or promise manifoldness. Return object snapshot and vertex/edge/polygon counts; clean only owned intermediate data on failure and disclose possible effects when mutation began.
- createMaterial(options) creates owned opaque Principled/output nodes with linear RGB components in 0..1, alpha 1, roughness default 0.5 and metallic default 0, both in 0..1. Return a typed material handle, name and parameters. assignMaterial accepts only local single-user mesh data, rejects linked/shared data, applies one DATA slot to the whole mesh and bounds 8192 polygons/32768 loops. It never copies silently or edits sibling objects.
- createCamera(options) creates an unparented perspective camera at world location aimed at target using -Z/Y tracking and XYZ Euler rotation. Reject coincident target and nonfinite/out-of-range coordinates. Lens defaults 50 mm within 1..500; clipping defaults 0.1/1000 with 1e-6 <= start < end <= 1e12. setActive defaults false; true permanently selects scene.camera. Return object snapshot and lens/clipping/active fields.
- createAreaLight(options) uses the same placement convention, linear RGB white by default, power default 1000 W within 0..1e12 and size default 5 within 1e-6..1e6. Return object snapshot and color/power/size.

## Native GUI render and recovery

startRender accepts caller-known renderId UUID before transmission and optional width/height default 512, each within 1..4096 and at most 16777216 pixels. It uses the current active camera, frame and engine. Requested resolution, percentage 100 and PNG 8-bit RGBA persist so a saved .blend reproduces the result. Do not temporarily swap cameras or engines. getRender accepts a session/render handle. Session-only render/artifact handles survive explicit reconnect while each request still carries current generation. A lost start reply is OUTCOME_UNKNOWN: callers retain their ID, reconnect explicitly and inspect it. Duplicate IDs are rejected; this is not replay or idempotency.

Render jobs carry handle, immutable start generation, scene identity/name, camera object ID, engine/frame/dimensions and UTC start time. Named variants are running/finalizing, succeeded with finishedAt/artifact, or cancelled/failed/unknown with finishedAt and typed code/message/effects. One native render is active at a time. No programmatic cancellation is promised; actual native Esc can be observed. Script job termination and disconnect do not cancel native rendering.

GUI invocation uses INVOKE_DEFAULT with write_still=True into a unique owned PNG stage. Handlers only flag observations. A timer finalizes after the native job ends, verifies scene UID/generation/render-init ownership, moves the stage to a distinct owned artifact pathname and conditionally restores only render.filepath when it still equals the owned temporary path. Camera/frame/engine/resolution/PNG settings persist. Foreign render_init, load, undo or uncertain restoration produce unknown and no artifact; save/new render remain BUSY until temporary path references are resolved. During render only render.get, artifact.read/release and disconnect are allowed. Global Render Result exclusivity, scene copies and arbitrary addon/compositor/handler sandboxing are not promised.

## Artifacts and explicit destinations

Artifacts contain session/artifact handle, render ID, immutable start generation, image/png MIME, byte count, width/height and expiry. Retain at most four artifacts, each at most 32 MiB, total at most 128 MiB, for 600 seconds. Terminal job metadata has cap eight/600 seconds; active jobs are not TTL-evicted. readArtifact accepts owned handle, offset and maxBytes within 1..196608, returning exact offsets/total/dataBase64/eof. Offset equal to size returns empty EOF; beyond-size offsets fail. releaseArtifact releases only the owned artifact. There is no arbitrary filesystem read method.

saveArtifact and saveBlendCopy accept an explicit absolute .png or .blend destination, an existing parent directory and overwrite default false, returning path/bytes/source session/current generation. Do not add implicit extensions or hidden-folder-only restrictions. Publish through an owned same-parent stage: hardlink no-replace for default behavior, os.replace only for explicit overwrite. Unsupported filesystems fail rather than using a nonatomic fallback. Artifact export copies to a distinct inode so releasing private artifacts cannot alias user output.

Native .blend save uses copy=True and relative_remap=True, retains the current working filepath and preserves relative-asset resolution when reopened; asset packing is not included. Reject known dirty external images with native ALWAYS auto-save during preflight without changing global preferences. Save handlers can have effects. File publication is outside undo/rollback and a sent timeout can have published. Clean only exact owned stage/@/known backup files, never a published destination or preexisting user backup.

## Acceptance and verification

One secret-free source TS inspects the loaded scene, creates a five-vertex pyramid, assigns opaque material, adds active camera/area light, starts a caller-ID native render, polls, reads bounded PNG chunks, saves PNG and a .blend copy at explicit destinations, then reopens the .blend and rerenders the same camera/settings. Preserve the actual PNG/.blend/TS as ignored or external task-owned user artifacts, never Git. Headless and MCP later consume the same scene core; background EXEC can block its Python RPC and does not inherit GUI async guarantees.

Observe actual invalid topology/shared mesh rejection, no-overwrite/explicit overwrite, chunk boundaries/release/expiry, stale reconnect and render ownership/cancellation where available. Units cover only real first-party validators/state/chunk logic, never upstream behavior, static manifests, artificial child/filesystem fixtures or a separate example package. Record unsupported observations precisely. Collect source checks, applicable Evidence, independent complete review, actual Blender results and exact-head CI in one cause round; reuse same-head CI full lint/native guards/distribution build rather than duplicate local aggregates. Green checks and fresh self/independent review lead directly to Ready/merge under the standing mandate.

Final integrated acceptance additionally covers isolated headless scene/render/save lifetime, typia MCP native images in real clients and installation of the latest extension ZIP. Those remain following Drafts; package publication and release are not authorized.

## Primary-source basis

These links were inspected during the closed design research. They support the accepted behavior above, not a claim that this new feature has already passed actual acceptance.

- [Blender 5.2 GUI render invoke/start/end](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/editors/render/render_internal.cc): invoke owns a native window-manager job, write_still reaches the native start, and a new invocation can clear global Render Result. A later global result is not exclusive proof of our render output.
- [Pipeline completion ordering](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/render/intern/pipeline.cc#L1936) and [later cleanup](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/render/intern/pipeline.cc#L2003): callback completion precedes pipeline/global rendering cleanup, so a complete handler alone does not prove native job termination.
- [Python job query](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/python/intern/bpy_app.cc#L767) and [window-manager query](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/windowmanager/intern/wm_jobs.cc#L820): running-job observations do not establish exclusivity over pending work. [Handler API](https://docs.blender.org/api/5.2/bpy.app.handlers.html) describes render_init/complete/cancel; register and remove only our own handlers.
- [save_as_mainfile API](https://docs.blender.org/api/5.2/bpy.ops.wm.html#bpy.ops.wm.save_as_mainfile): copy retains the current document, relative_remap is supported, and check_existing is an overwrite warning rather than a no-replace race guarantee.
- [Native save implementation](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/windowmanager/intern/wm_files.cc#L4004): save_modified_images ALWAYS can run before the copy branch; copy/remap reach the writer and background support does not require a window. [Native backup and temporary writes](https://github.com/blender/blender/blob/blender-v5.2-release/source/blender/blenloader/intern/writefile.cc#L2045) require an owned-stage publication boundary instead of cleaning user backups.
- [os.link](https://docs.python.org/3.13/library/os.html#os.link) and [os.replace](https://docs.python.org/3.13/library/os.html#os.replace) support explicit no-replace/overwrite publication choices. Unsupported filesystems fail without a hidden nonatomic copy fallback.
