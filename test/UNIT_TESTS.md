# First-party unit verification

Run `pnpm test` from the repository root to execute every named case through the AutoMovie-style DynamicExecutor layout, and `pnpm run test:types` separately for ordinary compiler diagnostics. Run `pnpm run lint` separately for the configured correctness and declaration-lint diagnostics. Local workspace consumers resolve TypeScript source without a preparatory build. No case-selection grammar or synthetic runner tests are provided.

The CLI case verifies saved-file and Text argument boundaries, optional machine output, explicit discovery probe consent and timeout bounds, and doctor path grammar. It preserves the existing immutable input, origin-label exception, duplicate/missing operands, and verbatim script-tail cases. The SDK framing case verifies independent wire fixtures, fragmentation, coalescing, strict decoding, byte limits, and encoder refusals.

The SDK scene-input case verifies the actual client validators' finite coordinates, independent topology caps, detached copies, material and camera/light parameters, handle lifetime, and query cursor bounds. Its render/artifact case verifies caller-owned UUIDs, native-job variant and PNG provenance consistency, canonical-base64 response windows, exact offsets, progress, EOF, and byte limits. These observations prove admission and readback validation rather than native mesh correctness, PNG contents, artifact retention, or Blender rendering.

The runtime cases exercise the actual internal journal and state owner consumed by ScriptJob. Independent text and byte fixtures cover incremental UTF-8, split-token redaction, stream tags, paging, retention gaps, immutable reads, and invalid cursor/budget refusals. State observations cover phase order, terminal ownership, exit versus bootstrap/uncertain outcomes, snapshot copies, and bounded credential-free metadata. Direct internal imports follow the existing framer case; no public export or helper exists solely for tests.

These units do not start Blender, sockets, or child processes. Actual descriptor discovery/probes, doctor metadata, Text staging, imports, source diagnostics, pipe completion, scene creation, render ownership, PNG output, explicit file publication, saved-file reopening, and UI observations belong to direct product validation; there are no filesystem fixtures or mocked launchers.

Each named case answers the [testing contracts](../.agents/skills/contracts/testing.md); its package-local Evidence configuration selects those cases. The independent `test.yml` workflow checks Evidence and runs the explicit test lint guard, ordinary type checking, and units on Ubuntu and Windows without building producers. The separate `build.yml` workflow checks configuration, product lint, formatting, and distribution builds. Product validation and remaining scope are tracked in [issue #6](https://github.com/samchon/blendia/issues/6).
